# 첫 개발 구간 상세 명세

## 목표와 범위

M0~M2: 질문→모델의 도구 선택→교육 조회→결과 기반 답변→같은 대화 후속 질문을 먼저 완성한다. 최종 프로젝트는 통합 업무지원이지만 첫 동작은 기존 교육 모듈로 검증한다. PDF100개는 수령했으며 이 구간에서 파싱·게시 완료를 선행 조건으로 삼지 않는다.

MOD-04→07→03→02→01의 계약과 MOD-09의 actor 경계를 검토한다. 처음은 test_stub actor를 쓰고 실제 세션은 M3에서 완성한다. 문서가 미게시인 이 구간은 knowledge_enabled=false, 허용 도구는 list_trainings/get_training뿐이다. A/B snapshot 준비가 안 됐다는 이유로 교육 실행을 막지 않는다.

## 첫 구간의 사용자와 HTTP 경계

- APP_ENV=local/test에서만 AUTH_MODE=test_stub을 허용한다. 서버 시작 설정 TEST_ACTOR_ID의 test-a/test-b fixture를 CurrentActor 어댑터에 고정한다. 직원 요청의 user_id/role/사용자 선택 헤더로 바꿀 수 없다.
- 두 사용자 격리는 같은 테스트 DB를 사용하는 두 앱/TestClient의 서로 다른 서버 설정 또는 테스트 DI로 검증한다. 외부 클라이언트에 actor 변경 API를 제공하지 않는다.
- stub은 로컬/test 전용이며 운영 설정에서 시작을 거절하고 네트워크 노출은 loopback으로 제한한다. 실제 로그인·문서 ACL/권한 철회·CSRF 완료를 주장하지 않는다. 변경 요청 Origin 검사는 M0부터 둔다.
- M3의 local_session은 동일 CurrentActor 포트로 교체한다. 브라우저 쿠키 기반 상태 변경은 세션과 CSRF 검증을 함께 적용한다. 계정/회신 수단·지원 범위 fixture는 M3/M5 전에 확정한다.
- M1은 MOD-02의 최소 SDK 반복·상한·메모리 observer, M2는 MOD-01 영속 observer·상태·receipt·run 복구를 연결한다. 두 단계의 비활성 RetrievalContext는 APP-02 DisabledRetrievalContextProvider가 제공하며 M3부터 MOD-11 실제 provider를 주입한다.

## 고정 교육 fixture


모든 일정은 가상 데이터입니다. 고정 테스트 기준 시각은 `2026-10-16T10:00:00+09:00`입니다. 아래 표의 시각은 한국 시간입니다.

| 코드 | 교육명 | 시작 | 종료 | 장소 | 상태 |
|---|---|---|---|---|---|
| `TR-SEC-001` | 신입사원 정보보안 교육 | 10/20 14:00 | 10/20 16:00 | 3층 교육장 | scheduled |
| `TR-COLLAB-001` | 신입사원 협업 도구 교육 | 10/22 10:00 | 10/22 11:30 | 온라인 | scheduled |
| `TR-ONBOARD-001` | 신입사원 회사 소개 | 10/16 11:00 | 10/16 12:00 | 2층 세미나실 | scheduled |
| `TR-SEC-OLD` | 이전 정보보안 교육 | 10/13 14:00 | 10/13 16:00 | 3층 교육장 | completed |
| `TR-PRIVACY-001` | 개인정보 보호 교육 | 10/21 15:00 | 10/21 16:00 | 온라인 | cancelled |
| `TR-DATA-001` | 데이터 활용 기초 | 10/26 09:00 | 10/26 10:00 | 4층 회의실 | scheduled |
| `TR-CS-001` | 고객 응대 기초 | 10/27 13:00 | 10/27 15:00 | 2층 세미나실 | scheduled |
| `TR-LEAD-001` | 업무 계획 세우기 | 11/02 10:00 | 11/02 11:00 | 온라인 | scheduled |
| `TR-SALES-001` | 영업 업무 소개 | 10/15 10:00 | 10/15 12:00 | 2층 세미나실 | completed |
| `TR-SAFETY-001` | 사무실 안전 교육 | 10/30 14:00 | 10/30 15:00 | 3층 교육장 | scheduled |

연도는 모두 2026년입니다. 각 교육의 설명도 한두 문장 작성합니다.

첫 두 교육의 ID는 문서의 API 예시와 맞춥니다.

- `TR-SEC-001`: `11111111-1111-4111-8111-111111111101`.
- `TR-COLLAB-001`: `11111111-1111-4111-8111-111111111102`.

나머지 ID도 seed에 고정값으로 보관합니다. DB 삽입·재실행 때마다 새 UUID를 생성해 같은 샘플을 중복시키지 않습니다.

### seed와 실제 현재 날짜

고정 fixture의 날짜는 테스트 재현용입니다. 데모 seed의 anchor_date 기본값은 서버의 오늘 한국 날짜입니다. base Monday는2026-10-12, target Monday는anchor_date가 속한 주의 월요일입니다. 두 월요일의 날짜 차이만큼 모든 fixture의 시작/종료를 동일하게 이동합니다. 요일·시각·기간·주 간격·UUID·코드는 유지한다. status는 아래 fixture_mode에 따라 결정하고 개발 DB의 샘플 날짜만 갱신합니다. 임의 anchor 요일에서도 회사 소개 교육은 해당 주 금요일이며 항상 ‘오늘’이 되는 것은 아닙니다.

테스트는 anchor를 2026-10-16으로 고정합니다. 데모용 날짜를 바꾸기 위해 일반 사용자가 HTTP 요청으로 서버 clock을 덮어쓰게 하지 않습니다.

### date_preset의 실제 구간

모든 경계는 KST00시이며 starts_at을 시작 포함·종료 제외로 비교합니다. scheduled 상태를 적용하되 현재 시각 이후만 남기는 암묵적 필터는 두지 않습니다.

| preset | 시작 / 종료 제외 | 고정 기준10/16 10시의 예 |
|---|---|---|
| today | 오늘 / 내일 | [10/16 00시,10/17 00시), 회사 소개1건 |
| this_week | 이번 월요일 / 다음 월요일 | [10/12,10/19), 회사 소개1건; completed 제외 |
| next_week | 다음 월요일 / 그다음 월요일 | [10/19,10/26), 보안·협업2건 |
| next_30_days | 오늘 / 오늘+30일 | [10/16,11/15), scheduled7건 |
| custom | start_date / end_date_exclusive | 둘 다 필수, 최대90일 |

0시 경계를 검증하려면 같은 날짜의09시 scheduled fixture를 테스트에서 추가하고 현재10시여도 포함됨을 확인합니다. 기존11시 회사 소개는0시/현재 시각의 차이를 입증하는 사례가 아닙니다.

계약상 입력/출력은 [API](04-api-spec.md)와 [Agent 정책](05-agent-execution.md)을 따른다. seed의 교육 설명은 구현 시 가상 일정 데이터로 추가하되 PDF 규정의 사실로 사용하지 않는다.

이 구간의 게이트는 교육 범위 T-01~03/05~12/19다. T-04 문서 권한 철회는M3, T-07은교육 ID만M2/문서 인용M3/티켓·action M5, T-10의 여러 검색 인용은M3에 적용한다. 미구현 문서·티켓 검증까지 첫 구간에서 요구하지 않는다. run 상세는 [수락·복구 계약](contracts/01-run-lifecycle.md)을 따른다.

다음 단계는 이미 수령한 PDF의 manifest·파싱·현재 권한·판본을 검수하고 raw RAG를 붙이는 것이다. PDF나 규정 본문을 자동 제작하는 단계가 아니다.

## anchor 이동과 fixture 상태

fixture_mode는 fixed_status 또는 live_clock이며 설정에 명시한다. fixed_status에서는 starts/ends 평행 이동 후 status_override를 유지한다. 고정 상태 재현 시나리오는 명시 status_override를 유지하고 보고서에 표시한다. 실제 시간 진행 데모는 cancelled를 우선 보존하고 ends<=clock이면 completed, 그 외 scheduled로 재산출한다. 두 모드를 섞지 않고 fixture manifest에 모드·anchor·clock을 기록한다.
