# 인프라

## 로컬 실행 기반

Docker Compose로 웹 정적 파일/프론트엔드, FastAPI 백엔드, PostgreSQL+pgvector를 재현한다. 수집·Wiki·평가는 동일 백엔드 패키지를 사용하는 별도 CLI 프로세스다. 외부 의존은 선택한 LLM·임베딩 API 한 공급자부터 시작한다.

| 자원 | 용도 | 경계 |
|---|---|---|
| PostgreSQL | 업무·대화·권한·문서·Wiki·실행 기록 | 단일 DB, 모듈별 쓰기 소유권 |
| pgvector | 원문 및 Wiki 검색 벡터 | 모델·차원·색인 설정 일치 검증 |
| `data/raw/pdfs/` | 사용자 PDF 원본 입력 | 서버에서 임의 경로 입력 금지 |
| 비공개 artifact 볼륨 | 불변 PDF·파싱·색인·빌드 산출물 | 공개 정적 경로로 노출하지 않음 |
| 평가 산출물 경로 | 설정·측정값·검수 보고서 | 제한 문서 본문·정답 공개 여부 별도 관리 |
| 환경 설정/비밀 | DB·모델 키·세션 비밀 | Git·브라우저·로그에 제외 |

입력 폴더와 서비스가 제공하는 원본 저장소는 논리적으로 구분한다. 입력 파일이 교체되어도 게시된 판본의 PDF를 덮어쓰지 않는다. PDF 반환은 권한 검사 API를 거친다. 대용량 객체 저장소·클라우드 배포는 후속 선택이다.

## 신뢰 경계

브라우저·사용자 메시지·PDF 본문·Wiki·LLM 출력은 실행 권한의 근거가 아니다. 사용자·역할은 서버 세션, 문서 ACL은 게시 메타데이터로 결정한다. PDF 안의 지시문은 자료로만 취급한다. 파일형식·크기·페이지·추출시간 상한은 수집 설정에 기록하고 비밀번호 PDF·손상 파일·지원 안 되는 스캔은 보고 후 게시에서 제외한다. OCR을 쓰면 그 방법과 검수 상태를 기록한다.

## 장애·트랜잭션

모델 응답이나 파싱을 기다리는 동안 DB 트랜잭션을 열어두지 않는다. 수락/완료·스냅샷 전환·Wiki 게시·티켓 확정은 소유 모듈의 짧은 원자 작업이다. 실패한 빌드는 마지막 정상 게시본을 유지한다. 테스트 DB·실험 DB는 개발 DB와 분리한다.

## 초기 제외

Redis·Kafka·Kubernetes·vLLM·Kubeflow·GPU 서버는 사용하지 않는다. 큐가 없어도 CLI 작업의 체크포인트·재실행·게시 상태를 기록한다. 프로세스 수와 모듈 수는 일치할 필요가 없다.
