# 통합 업무지원 시안 사용 순서

2026-10-17. 서비스 구현은 보류하고 기존 정적 시안만 확장했다. [미리보기](http://127.0.0.1:8787/prototypes/work-assistant/)를 연다. 첫 화면 하나에서 시작하고 추천 질문·직접 입력으로 흐름을 이어간다. 검토용 상단 탭과 상태 선택창은 사용자 피드백에 따라 제거했다. 다른 흐름을 보려면 새 대화로 돌아온다.

## 규정과 PDF 출처

1. 첫 화면의 외부교육비 지원 질문 선택.
2. 외부교육비150만원/연300만원과 사전 승인·필수교육 예외·출장비 분리 확인.
3. 인용1 또는 문서 행을 눌러 ED-030·판본·사건 기준·원문1쪽 확인.
4. PDF1쪽 열기로 제공된 원본을 새 탭에서 확인. URL의 #page는 뷰어 힌트다.

## 과거 규정

1. 첫 화면의 ‘9월29일 출발한 수도권 출장’ 질문 선택. 답변은 확인된 출발일만 표시하고 사용자가 말하지 않은 복귀일은 만들지 않는다.
2. 종전 GA-082의 수도권1박8만원과 출장 시작일 기준 확인.
3. 현재 기준과 비교를 눌러 별도의10/16 출발 가정에서 현행12만원과 비교.
4. 각 인용으로 원문을 확인한다. 기존9월 출장에12만원을 소급 적용하지 않는다.

외부교육비 답변의 ‘9월에 시작한 교육도 같은 기준이야?’는 교육비 문맥에서 시작일 확인으로 이어진다. 새 대화의 모호한 ‘같은 기준’은 이전 대화에서 가져오지 않는다.

## IT 요청

1. 첫 화면의 VPN 접속 오류 질문 선택. 사용자 설명·대상 서비스·발생 시각·영향·긴급 여부를 수정.
2. 긴급 업무가 있으면 사유가 필수, 자산번호는 미확인 상태로 둘 수 있다.
3. 요청 내용 확인을 눌러 preview를 읽는다. 이때 아직 접수되지 않는다.
4. 수정은 입력 화면으로 돌아가고 취소는 접수 없이 종료한다.
5. 이 내용으로 등록(시안)을 누르면 DEMO-IT 번호와 접수/담당 배정 전 상태를 표시한다.
6. 접수 예시 완료 후 요청 내용 보기로 같은 시안 번호를 확인한다. 만료 등의 예외 상태는 설계 기준으로 유지하며 별도 상태 선택 메뉴를 제공하지 않는다.

## 유지할 원칙

기존 밝은 중립색·절제한 청색·목록/대화/상세 구조를 유지했다. Wiki를 원문 출처로 표시하지 않고 A/B 설정을 직원 화면에 넣지 않는다. 제한 문서 상태는 제목·내용을 노출하지 않는 일반 안내만 보여준다.

응답과 접수는 고정 시안이며 실제 검색·AI·인증·업무 실행이 아니다. PDF 원본은 변경하지 않았다. 설계 차이는 [PDF 반영 보정](../corpus/03-received-pdf-adjustments.md), 수령 관리정보는 [100개 목록](../corpus/02-received-register.md)에 기록했다.

입력 경계는 접근성 보정 토큰을 사용한다. 서비스 연결 시 폼 수정은 [revise API](../04-api-spec.md)로 새 action을 받는다. 현재 시안의 로컬 편집·가상 등록은 이 서버 계약의 구현 검증이 아니다.

## 계약 보정 후 검토 순서

9월 교육비를 물은 뒤 “9월30일에 시작해”로 답하면 종전 원문으로 이어진다. 출장 날짜와 지역도 나눠 답할 수 있다. 교육 신청 접수 기간은 IT 폼으로 분기하지 않는다.

VPN 폼에는 사용자 원문 이외의 발생 시각·영향·긴급 여부를 채우지 않는다. 입력은 대화 이동 후 보존되고, 요청 내용 확인(revise) 성공 시 pending preview를 만든다. 내용 수정 진입/수정 취소는 기존 pending을 유지하며 저장 성공만 교체한다. 만료/취소는 편집으로 되살리지 않고 대화에서 새 요청을 명시한다. 실제 접수는 아니다.

상태 메뉴를 다시 추가하지 않았다. 검증자는 tests/browser-flows.cjs로 ?qa=1의 명시적 fixture를 호출해 근거 부족·접근 제한·오류·세션 만료·응답 불확실을 재현한다. [실행 방법](../../prototypes/work-assistant/tests/README.md)을 따른다.
