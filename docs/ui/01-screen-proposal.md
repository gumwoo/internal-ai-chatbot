# 통합 업무지원 화면 요구사항

상태: 2026-10-17 통합 범위의 클릭 가능한 정적 시안을 반영했다. PC 우선·기본 모바일·대화 목록/중앙 대화/선택적 상세 구조와 기존 [시각 토큰](../../DESIGN.md)을 유지한다. [시안](../../prototypes/education-agent/README.md)은 실제 서비스 구현과 구분한다.

## 기본 구조

| 영역 | 기능 |
|---|---|
| 왼쪽 | 본인 대화·새 대화·현재 사용자·로그아웃 |
| 중앙 | 질문/후속 질문, 교육·문서·티켓 결과, 입력·처리 중/실패 |
| 선택적 오른쪽 | 교육 상세, PDF 원문/페이지·판본·기준일, 티켓 내용/상태 |

좁은 화면은 탐색을 접고 상세를 전체 너비로 연다. 닫을 때 기존 메시지 위치·포커스를 복원한다. 장식용 KPI·불필요한 카드·그라데이션·과장된 Agent 애니메이션을 추가하지 않는다. 기존 밝은 업무 화면의 정보 위계를 유지한다.

## 주요 사용자 흐름

1. 질문/후속: 교육·IT·규정 질문을 같은 입력창에서 처리한다. 주제를 바꾸었다고 이전 교육을 임의 선택하지 않는다.
2. 원문: 답변 인용→문서명/판본/시행 구간/조회 기준일→실제 물리 페이지와 인용 구간→PDF 보기. Wiki를 규정 출처로 표시하지 않는다.
3. 과거 질문: “당시 기준”과 현재 기준을 구분한다. 두 시점 비교는 어느 인용이 어느 시점인지 보여준다.
4. IT 지원: 증상 설명→준비된 subject/description/category 확인→확인/취소→실제 ticket ID와 상태. 확인 중 반복 클릭을 막는다.
5. 응답 유실: 등록 실패로 단정하지 않고 action을 재조회한다. 새로고침도 실제 상태를 읽는다.
6. 권한/세션 변경: 제한된 이력은 일반 안내로 대체하고 해당 본문·인용 캐시를 지운다. 로그인 만료는 재로그인 흐름으로 안내한다.

## 상태와 문구

일정0건, 모호해 추가 질문, 근거 부족, 시스템 실패, action_pending, confirmed를 구분한다. pending에서 “등록했습니다”를 표시하지 않는다. 동기 API의 대기 화면은 “처리 중”만 표시하며 추정 도구 단계·스트리밍은 보여주지 않는다. 관리자용 A/B 진단·Wiki 빌드 상태를 일반 직원 화면에 노출하지 않는다.

## 계약·접근성

교육/티켓 상세는 서버 DTO를 사용한다. 모델 문장에서 날짜/ID/등록 결과를 추출해 기준 데이터로 쓰지 않는다. API는 [04](../04-api-spec.md), 모듈은 [08](../modules/MOD-08-chat-ui.md)를 따른다. 키보드·IME Enter 처리·포커스 표시/복원·오류 알림·모바일 긴 표/긴 PDF 제목을 검증한다.

## 기존 시안의 위치

시안은 원문 PDF 링크와 고정 응답, 로컬 입력/상태 전환으로 세 흐름을 검토한다. 실제 로그인·LLM·권한 검사·Wiki·자동 PDF 검색·티켓 등록은 없다. 요청 번호는 DEMO-IT 접두사를 쓰고 실제 접수가 아님을 표시한다. 세 흐름의 클릭 순서는 [시안 사용 순서](02-prototype-walkthrough.md)를 따른다.
