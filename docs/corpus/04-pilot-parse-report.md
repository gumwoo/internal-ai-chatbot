## 검사 방법과 한계

- **숫자 일치:** pdfplumber 기본 텍스트 추출(`extract_text`)의 숫자·금액·날짜 토큰이 block 원문에 같은 개수 이상 있는지 본다. block도 같은 라이브러리의 줄 추출에서 오므로 **독립 검증이 아니다**. 다른 추출 경로(표 셀 추출)와 줄 추출의 일관성 검사에 가깝다. 사람의 원문 대조 표본은 아직 없다.
- **인용 역추적:** 청크의 모든 span(페이지·block·Unicode offset)이 저장된 페이지 원문의 같은 위치를 가리키는지 확인했다.
- **표:** 표 제목(바로 위의 "별표/별지/붙임/표 N" 줄)과 열 헤더를 청크마다 붙인다. 다음 페이지에서 같은 열 헤더로 다시 시작하는 표는 같은 support_group으로 잇는다(IT-037 표 1 확인).
- **머리말·꼬리말:** 지우지 않고 kind=header/footer로 표시해 청크에서만 뺀다.
- **줄바꿈(알려진 한계):** 원문 줄은 그대로 보존한다. 검색용 텍스트에서만 오른쪽 여백까지 찬 줄을 공백 없이 잇는다. 표본을 보면 이 PDF의 줄바꿈은 글자 단위("업무⏎상")와 단어 경계("기본⏎사항", 공백 손실)가 섞여 있다. 단어 경계에서는 검색용 텍스트의 공백이 하나 빠진다. 근거 표시·인용은 원문 줄을 쓰므로 영향이 없다. 몇 곳이 어느 쪽인지는 세지 않았다.
- **빈 양식:** 양식 표의 빈 칸은 사실로 만들지 않지만, 필드명 행은 청크에 들어간다(34개 표).
- **OCR:** 100개 모두 텍스트 레이어가 있어 OCR을 쓰지 않았다. 스캔 PDF 처리는 구현하지 않았다.

## 임베딩 차원·입력 형식 선택 근거(D-32, 평가 아님)

ED-030·GA-082·GA-090·IT-037의 청크 74개에 대해, 손으로 쓴 질의 10개의 정답 청크 순위를 쟀다. 임베딩은 `gemini-embedding-2` 무료 티어다.

| 설정 | hit@1 | hit@5 | MRR |
|---|---:|---:|---:|
| 1536차원 + 작업 지시문(`task: search result | query:` / `title: … | text:`) | 9/10 | 10/10 | 0.95 |
| 768차원 + 작업 지시문 | 9/10 | 10/10 | 0.95 |
| 1536차원, 지시문 없음 | 8/10 | 10/10 | 0.90 |

- 768과 1536의 차이는 이 표본에서 보이지 않았다. 표본이 작아 판단 근거로는 약하다. D-32대로 1536을 유지한다(컬럼 `vector(1536)`).
- `task_type` 파라미터는 값을 바꿔도 같은 문장쌍의 코사인 유사도가 같았다(0.6754). 무시되는 것으로 보고(추정, 공급자 문서로 확인 안 함) 입력 앞 지시문을 쓴다(`gemini-embedding-2-prefix-v1`).
- 응답 벡터는 1536차원에서 이미 길이 1이었다. 저장 전에 한 번 더 정규화한다.

## 무료 티어 한도(관찰)

- 분당 100건이며 **묶음 안의 입력 하나를 1건으로 센다**(429 응답의 quotaId `EmbedContentRequestsPerMinutePerUserPerProjectPerModel-FreeTier`, quotaValue 100).
- **일일 한도는 1,000건이다(2026-10-18 실측).** 429 응답의 quotaId `EmbedContentRequestsPerDayPerUserPerProjectPerModel-FreeTier`, quotaValue 1000. 분당 한도와 마찬가지로 입력 하나를 1건으로 센다. 공급자 문서 페이지에는 이 값이 없었다.
- 100개 전체 청크는 1,545개(파서 보정 뒤)라 무료 티어로는 하루에 색인할 수 없다(최소 이틀). 2026-10-18 시험 게시 시도는 464/1,545에서 일일 한도로 멈췄고, 받은 벡터는 캐시에 남아 다음 날 이어서 받을 수 있다. 진행 규칙(D-35: 무료 티어만, 유료가 필요하면 중단)에 따라 더 진행하지 않았다.
- 이전 메모: 일일 한도는 공급자 문서에서 확인하지 못했다. 그래서 준비 산출물 캐시(`data/staging/embeddings/`, git 제외)로 같은 입력을 다시 보내지 않고, 분당 100건으로 속도를 조절한다. 한도에 걸려 중단되면 받은 벡터는 캐시에 남는다.
- 응답에 사용량(metadata)이 없어 토큰 수는 기록하지 않는다(0으로 채우지 않음, T-19).

|---|---|
| 구성 검사(T-18) | 100파일·91 논리 키·종전 9건, 오류 0 |
| 시행일(effective_from) | 100건 모두 원문 근거(부칙 "제1조(시행일)" 또는 문서 정보 표 "시행일") |

| application_basis(제안) | 보정 문서의 사건 기준표에 있는 13건만 사건 기준, 나머지 87건 general_reference. 검수 필요 |
