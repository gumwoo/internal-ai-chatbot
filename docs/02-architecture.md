# 아키텍처 탐색

설계 검토의 상한은 모듈의 책임·공개 계약·소유권·협력이다. 클래스·파일 배치·알고리즘·SQL은 이 문서의 승인 단위가 아니다.

| 검토 단계 | 문서 | 핵심 질문 |
|---|---|---|
| 1 인프라 | [실행 기반](architecture/01-infrastructure.md) | 프로세스·스토리지·비밀·실패 경계는? |
| 2 애플리케이션 | [실행 단위](architecture/02-applications.md) | 웹·API·배치·평가가 어떻게 배포/실행되는가? |
| 3 레이어 | [의존 방향](architecture/03-layers.md) | 진입·유스케이스·업무·어댑터를 어떻게 구분하는가? |
| 4 모듈 | [12개 모듈](architecture/04-module-map.md) | 책임·데이터·계약의 소유자는? |
| 5 협력 | [시나리오](architecture/05-collaboration.md) | 수락·검색·게시·쓰기·실패가 어떻게 연결되는가? |

[검토 안내](architecture/00-review-guide.md)에서 시작한다. 동일 데이터베이스를 쓰는 모듈형 모놀리스이며, 모듈마다 별도 서비스나 네트워크 호출을 요구하지 않는다. 문서 범위 확대를 마이크로서비스 전환 이유로 삼지 않는다.
