# 요구사항

최종 MVP 기준이다. 첫 개발 구간의 축소 범위는 [12](12-first-milestone-spec.md), 모듈 배치는 [모듈 지도](architecture/04-module-map.md)를 따른다.

## 기능 요구사항

| ID | 요구 | 수락 기준 | 책임 |
|---|---|---|---|
| FR-01 | 교육 목록 | 한국 날짜·제목·페이지 조건으로 예정 교육, 정상 0건 구분 | MOD-04 |
| FR-02 | 교육 상세 | ID·상태·시간·장소·설명, 잘못된 ID·미존재 구분 | MOD-04 |
| FR-03 | Agent 도구 실행 | 허용 스키마만 호출, 결과에 따라 추가 조회·질문·완료 선택 | MOD-02/03 |
| FR-04 | 대화·후속 질문 | 사용자·대화별 상태 격리, 모호한 대상 되묻기, 재열람 | MOD-01/02 |
| FR-05 | 원문 검색·인용 | 허용된 PDF 원문만 반환, 문서·판본·물리 페이지·구간 확인 | MOD-05/06/11 |
| FR-06 | 실패와 기록 | 도구 실패·0건 구분, run·오류 단계·알려진 usage 기록 | MOD-01/02/07 |
| FR-07 | 화면 | 대화·교육·출처·티켓 확인·완료/실패 상태, 모바일 기본 지원 | MOD-08 |
| FR-08 | 재현 실행 | 별도 테스트 DB, 마이그레이션·명령·구성 고정, 비밀 제외 | APP-01~04 |
| FR-09 | PDF 수집 | 100파일/91문서/구버전9 검수, 원본 해시·파싱 보고서·스냅샷 | MOD-05/06 |
| FR-10 | 문서 권한 | 검색·Wiki·출처·PDF·대화 이력에 현재 권한, 기본 거부 | MOD-09 및 자원 소유 모듈 |
| FR-11 | 시점·개정 | 시행 구간으로 판본 선택, 과거 기준·두 시점 비교, 공백·충돌 표시 | MOD-05/11 |
| FR-12 | Wiki 관리 | 원문 주장 링크, 검수·게시·stale, 같은 corpus와만 결합 | MOD-10 |
| FR-13 | 검색 전략 비교 | 서버 고정 A/B, 원문 근거·동일 최종 예산, 재현 가능한 보고서 | MOD-11, APP-04 |
| FR-14 | 티켓 조회 | 본인 또는 허용 담당 범위만 목록·상세, 존재 정보 보호 | MOD-12 |
| FR-15 | 티켓 등록 | 준비→내용 확인→인증된 확인 API, 멱등 생성·감사·실패 복구 | MOD-12/08 |

## 비기능 요구사항

| ID | 요구 | 검증 |
|---|---|---|
| NFR-01 | 유한 실행 | 전체 60초·도구/모델 상한·외부 timeout·재시도 소유자 한 곳 |
| NFR-02 | 사용자·자원 격리 | 타인의 대화·티켓·제한 문서와 과거 답변 재노출 차단 |
| NFR-03 | 동시성 | 대화별 활성 run 하나, 다른 대화는 진행, 티켓 동시 확인 한 건 |
| NFR-04 | 원자성 | 질문 수락·완료, corpus 전환, Wiki 게시, 티켓 생성 각각 짧은 트랜잭션 |
| NFR-05 | 재현성 | clock·모델·프롬프트·corpus/wiki·권한 fixture·검색 설정 식별 |
| NFR-06 | 관측·정보 최소화 | 단계·ID·시간 기록, 비밀/제한 본문을 일반 로그로 남기지 않음 |
| NFR-07 | 비용 정직성 | 미확인 usage는 null, 구축·갱신 비용과 요청 비용 분리 |
| NFR-08 | 사용성 | PC 우선, 키보드·IME·포커스·기본 모바일 작업 |
| NFR-09 | 원문 추적 | 인용마다 실제 판본·페이지·구간 존재, 파서 변경 추적 |
| NFR-10 | 변경 대응 | 실패한 재색인이 기존 게시본 손상 없음, stale Wiki 혼합 금지 |
| NFR-11 | 쓰기 안전 | LLM이 확인을 위조할 수 없음, 서버 재인가·만료·멱등성·감사 |

## 정책의 기준 문서

권한·시점·PDF 메타데이터는 [문서 계약](corpus/01-metadata-contract.md), 모듈 DTO는 [공통 계약](contracts/00-shared-contracts.md), 실행 상한·도구는 [Agent 정책](05-agent-execution.md), 실험 조건은 [비교 프로토콜](13-retrieval-comparison.md)에서 단일 기준으로 관리한다. 규정 우선순위나 실제 HR 규칙은 개발자가 추정하지 않는다.
