# 최종 평가 보고서(작성 중)

> 상태: **미실행**. 100개 문서 임베딩이 1,545개 중 1,464개(2026-10-18 17:01 KST 실측)라 개발 DB 게시와 A/B 실행 전이다. 아래 결과 칸은 실행 뒤 채운다. 이 문서의 숫자 중 "실측"이라고 쓰지 않은 것은 예측이거나 설정값이다.

## 1. 무엇을 비교하나

- A raw: 원문 passage exact vector 검색 → 공통 정렬·예산 → Haiku 5.5 답변.
- B wiki_assisted: Wiki page 후보 5개 → 원문 링크 확장 → A와 같은 필터·원문 거리·예산 → 같은 답변 모델.
- 최종 근거는 두 방식 모두 원문 passage다. 엄격 B는 Wiki 미준비·stale·후보 0개를 실패로 센다(fallback 결과와 섞지 않는다). 기준: [비교 프로토콜](../13-retrieval-comparison.md), D-45~D-49.

## 2. 평가셋

- 150문항(dev 50 / holdout 100): 단일 30, 복수 40, 예외 25, 개정 20, 근거 없음 15, 권한 20.
- **모델 생성 문항이다.** 서브에이전트 3개가 원문(프로젝트 파서 추출 쪽별 텍스트)만 보고 만들었고, 다른 서브에이전트 3개가 정답 근거를 원문과 대조했다(ok 101 · 수정 49 · 제외 0). `scripts/check_eval.py` 기계 검사 오류 0. 사람 검수는 없다.
- 고정 질문 시각 2026-10-16 10:00 KST, 데모 계정(D-30)별 권한.

## 6. 전체 문맥 기준선(O-12) 실행 가능성

계정별로 질문 시각에 볼 수 있는 원문 passage 전체(종전 판본 포함 상한): 직원 115,062 · 부서장 118,906 · 인사 담당 116,931 token, 현행 판본만이면 108,428 · 112,272 · 110,297 token. 청크 1,545개는 실측, token은 프로젝트 추정식(UTF-8 바이트/3)이라 실제 토크나이저 값이 아니다. 모델 호출 20초 상한 안에 이 길이를 처리하는지는 측정하지 않았다.

## 7. 한계

- 규칙 채점(D-51)은 두 자리 이상 숫자·날짜·금액만 본다. 한 자리 수 사실과 숫자 없는 사실은 judge 보조 판정에 기댄다.
- A/B는 설정별로 따로 실행한다(문항 단위 교차 실행이 아니다).

- 모델 생성·모델 검증 문항이며 사람 검수가 없다. Wiki 의미 검수도 모델 검수다(D-48).
- dev 예산 스윕은 1회 실행이라 분산을 재지 않았다(D-49).
- 개정 경계 9쌍이 거의 같은 날짜(2026-10-01)라 시점 문항의 다양성이 낮다.
