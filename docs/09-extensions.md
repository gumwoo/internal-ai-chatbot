# 최종 MVP 이후 확장

이번 최종 MVP에는 Wiki 비교·문서 권한/개정·사용자 확인 후 IT 티켓 등록이 포함된다. 이 항목을 장기 확장으로 미루지 않는다. 구현 순서는 [개발 계획](08-development-plan.md)을 따른다.

| 확장 | 도입 조건·추가 경계 |
|---|---|
| 교육 신청·취소 | 신청 조건·정원·중복/승인·멱등 업무 계약 별도 정의 |
| HR/경비 신청·결재 | 정책·결재권·민감정보·실제 변경 검증이 준비됐을 때 |
| IT 담당 배정·처리/종결 | 티켓 상태 머신·지원자 권한·감사 범위 추가 |
| Agent 설정 관리 | 시스템 프롬프트·도구 허용 목록·버전·검수/rollback 요구가 생겼을 때 |
| MCP | 여러 도구 서버를 공통 계약으로 연결할 실제 필요가 있을 때 |
| LangGraph | 영속 실행·중단/재개·복잡한 분기가 실제 필요할 때. 부작용 멱등성 유지 |
| 온라인 Wiki LLM 탐색 | 초기 B와 별도 전략으로 비용/품질 실험 |
| Hybrid | 원문 Recall 실패가 확인됐을 때 A/B 공통의 별도 비교 ID로 추가([비교 프로토콜](13-retrieval-comparison.md)) |
| Reranker | 추가하지 않기로 했다(D-58: dev hard negative 인용 0.10, 오답 대부분이 답변 단계). 다시 검토하려면 새 평가 버전에서 dev로 판단한다(D-22) |
| 문서 관리 UI | CLI 운영에서 검수/게시/회수가 불편해질 때 |
| SSO·객체 저장소·큐 | 실제 사용자/동시성·운영 환경 요구가 생겼을 때 |
| GPU 서빙·Kubernetes | 별도 모델/인프라 목표가 생겼을 때. 현재 필수 아님 |

확장할 때 기존 도구에 승인 플래그 하나를 추가해 실제 쓰기를 허용하지 않는다. 별도 권한·확인·실패 복구·평가 계약을 먼저 정의한다.
